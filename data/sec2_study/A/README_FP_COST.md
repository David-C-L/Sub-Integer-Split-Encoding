# Follow-up 2 (v3, 2026-10-02): gate "false positives" and unstructured controls, current build

The previous version is `README_FP_COST_v2.md`. It used older gatespeed admission data and reported SIS sizes.

Per the author (2026-10-02), the Sec. 2 study characterises the data. This file therefore has baseline codecs and data
properties only. The SIS-vs-baseline result for these columns on the current build (sizes, sections, encode time)
moved to `../eval_from_study_runs.md` §2-3.

Source: benchmark host run `pulls/study_20261002_0006/study/` (evaluation `rev-addr-toplevel`, 524,288 leading rows, shipped
order). Parsed by `B/scripts/parse_host_study_20261002.py`; the CSVs are `B/csv/blank_cells_measured.csv` and
`csv/unstructured_controls.csv`. "Best non-SIS Nimble" is the smallest non-SIS Nimble encoding arm, with
uncompressed substreams. Auto/view without a candidate list is not usable for this (see the pull README).

- The two drug-cost columns compress to 20-24 bits/value except under Zstd (26-27 whole, 35-37 in 64-row blocks). OpenZL and
  BtrBlocks beat the best Nimble arm by 2.6-3.7 bits/value.
- The three count/bin columns have low entropy. Huffman or Zstd is already the best Nimble-side arm, and the
  codecs agree to within about 1 bit/value except Zstd on 64-row blocks.
- On instagram, only OpenZL (47.1) captures structure: Zstd and BtrBlocks stay at 60-61 bits/value.
- Zstd on 64-row blocks costs 1.1-3.4x the whole-column Zstd size on these columns.
- The older -4.6% to -63% SIS figures are not repeated here; their current-build counterparts are in
  `../eval_from_study_runs.md` §2. The older drug-cost rows used a different input (`*_bits`, 56-63 bpv
  baseline), so they are not comparable.

## Unstructured controls (`csv/unstructured_controls.csv`)

Generated by `scripts/gen_unstructured_controls.py` with N = 524,288:
- hashed_splitmix64: the splitmix64 output stream, seed 0, outputs 1..N.
- random_uint64: `numpy.random.default_rng(20261002).integers(0, 2**64, N, dtype=uint64)`.
- The sha256 of each file is in the pull's `raw/README.md`.

| column | distinct | P(bit=1) range | P(bit flips row to row) range | best non-SIS Nimble | Zstd whole | Zstd 64-row | OpenZL best |
|---|---|---|---|---|---|---|---|
| hashed_splitmix64 | 524,288 | 0.4985-0.5013 | 0.4986-0.5018 | 64.00 (Trivial) | 64.00 | 64.63 | 64.00 |
| random_uint64 | 524,288 | 0.4983-0.5018 | 0.4986-0.5023 | 64.00 (Trivial) | 64.00 | 64.63 | 64.00 |

- Both controls are all-distinct.
- Every bit is balanced and flips with probability 0.5 from one row to the next, so there is no bit-range
  structure.
- No baseline compresses either column.
- They are the negative reference for the class definition: a column with no compressible bit-range structure.
- They were not run on BtrBlocks/FastLanes: those harnesses take int64 inputs, and the values exceed INT64_MAX.
